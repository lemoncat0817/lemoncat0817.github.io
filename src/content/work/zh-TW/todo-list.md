## 這是什麼

一個待辦事項應用。功能不複雜：新增、刪除、修改、查詢，分類未完成與已完成，一鍵清除所有完成項目，一鍵全選或全取消，以及響應式版面。

我把它放進作品集，不是因為它技術上最難 —— **而是因為它是唯一一個「除了 Vue 什麼都沒用」的專案**。

## 為什麼這個專案值得一提

其他三個專案都站在工具庫的肩膀上：Element Plus 給了我元件、Pinia 給了我狀態管理、VueUse 給了我組合式函式。

這個專案什麼都沒有。`package.json` 的 dependencies 只有一個 `vue`。

所以每一件事都得自己想清楚：
- 狀態放哪裡？（元件內的 `ref`，因為規模還不需要 store）
- 清單怎麼渲染才不會有 key 的問題？
- 編輯中和顯示中的狀態怎麼切換？
- 響應式版面怎麼用手寫 CSS 做到？（沒有 Bootstrap 的 grid 可用）

這是**刻意的限制**。我想確認自己是真的會用 Vue，還是只是會用那些包在 Vue 外面的工具。

## 技術決策與取捨

### 不用狀態管理庫

待辦清單的狀態只有一份，而且只有少數幾個元件會用到。這種規模用 Pinia 是殺雞用牛刀 —— 多一層抽象，卻沒有解決任何實際問題。

**知道什麼時候「不要」用某個工具，和知道怎麼用它一樣重要。**

### 批次操作要考慮的邊界狀況

「一鍵全選／全取消」聽起來很單純，但要想清楚：按鈕現在該顯示「全選」還是「全取消」？答案取決於目前是不是全部都已完成。

「一鍵清除所有完成項目」也一樣：如果沒有任何已完成的項目，這個按鈕應該要禁用還是隱藏？

這些**邊界狀況才是真正花時間的地方**，功能本身反而很快就寫完了。

### 手寫響應式

沒有 CSS 框架，斷點和版面都得自己刻。這反而讓我更清楚 Flexbox 和媒體查詢實際上在做什麼，而不是背 `col-md-6` 這種類別名稱。

## 遇到的坑

**編輯狀態的焦點管理。** 點擊項目進入編輯模式時，輸入框應該自動取得焦點，否則使用者得多點一次。但 Vue 更新 DOM 是非同步的 —— 直接呼叫 `focus()` 會失敗，因為那個 input 當下還不存在。要等 `nextTick()` 之後才行。

這是我第一次真正理解 Vue 的非同步更新機制，而不只是「照著文件抄」。

## 成果

五項功能全部完成，桌機與手機版面都有處理。

## 如果重做我會怎麼改

1. **資料要能存下來。** 目前重新整理頁面待辦事項就消失了。用 `localStorage` 就能解決，這是最該補的一項。
2. **加上鍵盤操作。** 待辦清單這種高頻輸入的介面，理想上應該全程不用碰滑鼠 —— Enter 新增、Escape 取消編輯、方向鍵移動。
3. **刪除要能復原。** 目前刪掉就沒了，沒有確認也沒有還原。一個「復原」提示會讓體驗安全很多。
