## 這是什麼

樂活寵物咖啡廳是一個為寵物友善咖啡廳打造的九頁面品牌網站，用 Nuxt 4 靜態產生，從認識品牌、瀏覽菜單到線上訂位，都在同一個網站裡完成。

## 問題背景

形象網站常見的落差是「讓人想去」跟「讓人真的能去」中間的距離：圖片太大拖垮載入、內容藏在圖片裡搜尋引擎讀不到、網站沒講清楚怎麼去、幾點營業、訂不訂得到位子。

這個網站把這條路徑補齊：從瀏覽到訂位，每一步都有對應的頁面與明確的回饋。

## 我的做法

把敘事拆成九個各司其職的頁面：

- **`/reservation` 線上訂位。** 用 `vee-validate` + `zod` 做表單驗證，自動擋掉公休日與非營業時段，使用者不會選到根本訂不了的時段。
- **`/contact` 完整的地址地圖與營業時間。**
- **`/menu` 用真實資料呈現。** 價目表是結構化的 HTML，搜尋引擎讀得到，也套得上 Menu 結構化資料。
- **圖片全面交給 `@nuxt/image`。** 自動輸出多尺寸 WebP，載入快、畫質不打折。
- **元件庫用 shadcn-vue。** 建立在 Reka UI 之上，元件原始碼直接收進 `app/components/ui`，要客製化行為或樣式時，直接改專案裡的程式碼就好。

## 技術決策與取捨

### 為什麼是多頁面而不是單頁

訂位表單、完整菜單、常見問題這類內容，使用者是帶著明確目的來找的。比起在單頁裡捲動找資訊，有清楚網址、能直接分享或加書籤的獨立頁面更好用。用 Nuxt 讓「多頁面」和「靜態產生」可以同時成立：`nuxi generate` 把每個路由都輸出成靜態檔案，部署方式簡單，架構上是完整的多頁應用。

### 為什麼選 shadcn-vue 而不是傳統元件庫

傳統元件庫把元件包成黑盒 npm 套件；shadcn-vue 的做法是把原始碼複製進專案裡。訂位表單這種需要精準客製驗證邏輯與樣式的場景，直接擁有原始碼，比繼承泛用元件的所有預設行為更省事。

### 深色模式要跟原生控制項同步

`@nuxtjs/color-mode` 除了切換 CSS class，也會同步 `color-scheme`，讓瀏覽器原生的表單控制項、捲軸這些 CSS 管不到的 UI 一起換色，避免網站是深色、輸入框卻是刺眼的白色。

## 成果

九個頁面全部完成並可離線瀏覽（靜態產生），訂位表單會依當天日期即時擋掉不合法的選項，亮色與深色模式在所有頁面都完整支援。
